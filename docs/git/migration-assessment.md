# Gaze × GitDock 移植评估与交互草稿

评估与实施日期：2026-10-28。原始评估基于两个本地项目源码；后续实施结果记录在下方。

## 实施选择与进度

用户最初选择“独立 Git 工作区”，后根据实际界面调整为 GitDock 式三列布局：点击 Git 后以已导入项目列表替换项目文件树；主区提供“更改 / 历史 / 分支 / Stash”导航，中间显示对应列表，右侧显示差异和详情。Git 与文件入口共用同一个侧栏选中状态，互斥高亮。Git 页面隐藏文件标签栏，不再创建 Git 标签；切回项目文件会恢复原来的文件标签、文件树及编辑位置。下文及 HTML 中的两种布局保留为原始评估草稿。

已访问项目在当前会话中分别保留 Git 浏览状态与提交草稿，返回时刷新工作区并更新已打开差异，不因切换项目清空视图。仅显示当前选中项目，隐藏项目暂停工作区事件刷新；移除项目或更改根目录后卸载对应视图，避免沿用旧路径。

Git 项目卡片显示项目名、分支与变更数。变更用琥珀色边线，冲突用红色边线，当前项目单独显示选中背景。新增行数以绿色 `+` 标示，删除行数以红色 `−` 标示；汇总整个仓库相对 HEAD 的整体变更和未跟踪文本文件，部分暂存不重复累计，无法统计行数的文件保留 `*` 说明。所有已导入项目均显示，非 Git 项目明确标示不可用；仓库事件与窗口焦点触发刷新，读取失败清除旧统计，同一 worktree 的项目共享一次读取结果。

已在 `codex/gitdock-integration` 分支接入状态/差异、文件与代码块暂存/取消暂存、提交、同步、分支及标签/远程/submodule 管理、历史图及搜索、分支比较、Stash、文件历史/Blame、三阶段冲突与恢复操作；交互式 rebase、cherry-pick/revert 继续复用现有引擎和面板入口。

Gaze 仍管理唯一的项目列表与 SQLite 配置；Git 仓库身份仅在会话内绑定到已导入项目。移除项目后检查访问权限，同一 worktree 去重，监听真实 git dir/common git dir。Git 写锁与编辑器文件写操作互斥。提交保留未保存缓冲区；丢弃成功后才删除目标缓冲区旧内容；改写工作区的操作保存并锁定相关编辑器，结束后刷新文件与索引/LSP。

前端按需加载 Git 工作区，样式限定在 `.gaze-git-workspace` 并使用 Gaze 的主题和字体。原始可交互草稿已导出为同目录的独立 `interaction-draft.html`，用于保留两种布局对比，不连接真实 Git。

项目文件树同步显示 Git 状态：修改为琥珀色、新增/未跟踪为绿色、重命名为紫色、冲突为红色，并保留文字状态标记。父目录汇总变更与冲突，悬停说明暂存状态；不创建已删除文件的占位行。按展开项目读取并按仓库去重，Git 事件、文件变更与窗口重新获得焦点后更新，无需先打开 Git 工作区。状态读取失败或项目路径改变时移除旧标记。

克隆/初始化仍通过终端完成；非 UTF-8/特殊冲突继续使用外部工具；Windows/Linux 尚需实机验证。GitDock 的 MIT 许可保存在仓库根目录 `THIRD_PARTY_NOTICES.md`。

实施验证：前端 118 项测试通过，覆盖侧栏互斥高亮、项目列表与增删行数汇总、共享仓库去重、状态刷新与失败恢复、Git 页面无标签栏、各项目独立浏览状态与提交草稿、编辑器恢复；Rust 121 项通过、5 项按原有标记忽略；类型检查、Prettier、rustfmt、Clippy（`-D warnings`）、生产构建和 macOS `.app` 打包通过。忽略项包括两个 Git 大规模性能基准、两个需要真实大型工作区的检查和一个系统废纸篓检查。未运行浏览器/Computer Use 检查、Windows/Linux 实机测试或真实远程认证。

## 结论

可行性高。两边都是 Tauri 2、React 19、TypeScript 5.9、Rust 2021，Rust 最低版本均为 1.85；GitDock 使用本机 Git CLI，不要求给 Gaze 引入 libgit2。可复用的重点是后端 Git 领域逻辑、校验及其回归测试。前端组件可以适配，应用外壳和项目持久化应继续由 Gaze 管理。

建议采用“Gaze 内置 Git 工作流”：侧栏添加 Git 入口，差异、历史和冲突占用主工作区，保留当前文件标签与终端。不要整套嵌入 GitDock App，也不要增加第二份仓库注册表。首期也不需要先发布一个独立共享 crate；先复制有边界的模块并移植测试，等两个产品都需要同步演进时再考虑抽库。

## 必须解决的集成边界

### 项目身份、仓库身份、路径

Gaze 的 Project.id 是字符串 UUID，GitDock 的 RepositoryId 是 u64，后者依赖独立 JSON 仓库配置。Gaze 的项目根也可能只是仓库里的一个子目录。

建议由后端从 projectId 探测并返回仓库上下文：worktree root、git dir、common git dir、项目相对仓库前缀。Git 视图明确标注操作的是整个仓库。若项目指向仓库子目录，第一次进入时提供“打开仓库根目录”入口；不要静默只显示局部文件，却执行整仓库提交。

仓库路径是操作和快照隔离的依据，同一 worktree 被多个 Gaze 项目引用时应共用状态、失效与操作状态，避免重复监听和竞态。linked worktree 的快照按各自 worktree 隔离，共用 common git dir 的引用写锁延续 GitDock 现有方式。应用内写锁不能阻止终端或其他客户端的操作，因此写前快照校验、Git 自身锁和错误处理仍然必须保留。嵌套仓库 / submodule 首期不自动递归汇总，显示为独立仓库入口。裸仓库不提供工作区编辑和写操作。

### 自动保存与 Git 改写工作区

Gaze 已有 CodeReaderHandle.prepareFileOperation / finishFileOperation，可复用其停止自动保存、等待写入、临时禁止编辑的机制；App 的 handleFileOperation 已经展示了调用方式。但还需要按 Git 动作区分策略：

- 暂存：先保存选中的受影响编辑器，再读取新状态/快照并暂存。代码块基于旧快照时重新展示差异，不能悄悄换成另一个块。
- 提交：只提交索引。若存在未暂存修改，仍保持未暂存；不能把“保存所有文件”变成“全部暂存”。表单显示暂存文件数，未暂存项不进入本次提交。
- checkout / pull / merge / rebase / stash apply / revert：按整个 worktree 找到所有已打开的相关标签，包含不同项目中的同路径标签；先处理未保存内容，再锁定编辑器、执行 Git、失效缓存、重新加载、恢复编辑。无法安全保存或已有磁盘冲突时阻止操作。
- 丢弃：明确警告目标范围，目标缓冲区需要在确认后丢弃并从磁盘重载，不能在 Git restore 后自动保存旧内容。现有 prepareFileOperation 会先保存，不能不加区分地直接套用。
- 失败或取消：仍检查磁盘与 merge/rebase 状态，刷新文件树、编辑器、路径/符号索引和 LSP。取消进程不等于回滚仓库。

### 文件监听与缓存

Gaze watcher.rs 的 flush_events 过滤路径中的 `.git`，现有 FsChangeEvent 无法覆盖只改变索引、HEAD、refs 的操作。需要 Git 专用失效事件：工作区文件变更触发状态更新；Git 元数据变更触发状态/分支/历史更新；自身操作结束强制刷新受影响视图并合并短时间内的事件。

linked worktree 的真实 git dir / common git dir 可能在项目目录外，应根据 Git 探测结果监听，不能只监听 `<project>/.git`。首次仅加载当前仓库，后台摘要限并发、合并刷新，不在每次自动保存时遍历所有项目。

Git checkout 批量修改文件时，要同时处理 Gaze 原有索引与文件缓存，不能仅更新 Git 列表；在协调期间合并文件事件，结束后统一恢复。

### 命令、类型、依赖、错误与平台

- Gaze 继续通过 src/lib/api.ts 暴露 Git API；不要新增第二个前端 invoke 中心。命令注册到现有 Tauri builder。
- 将 GitDock 的领域模型适配到 Gaze 项目/仓库身份。可以去掉移入类型的 specta 派生、保持 Gaze 当前手写 TS 类型方式；无需仅为本次移植引入完整 specta 工具链。操作事件明确携带仓库身份及 operationId。
- GitDock 返回 String 错误，Gaze 有 GazeError / CommandError。保留可读原因，并增加可判断的 Git 错误情形（如快照过期、仓库忙、认证失败），不要吞掉 stderr。
- 若保留现有 DiffView，react-diff-view 与 refractor 是实际需要新增的依赖；需验证与当前 React 19 和构建配置兼容。暂不为复用 Gaze CodeMirror 而重写 diff 算法，也不假定这些依赖已安装。
- GitDock 有 Unix 专用 terminate_process_group，operations 无条件引用；外部打开路径使用 `/usr/bin/open`。Gaze 是跨平台产品，进程取消、工具探测、路径、回收站与外部合并工具必须单独适配；不能把 macOS 可运行当成 Windows/Linux 已支持。
- 沿用系统 Git 的 SSH agent / credential helper；当前代码设置 GIT_TERMINAL_PROMPT=0，认证失败应提供具体方向，不能假定应用内已具备密码/SSH 交互。Git hook、签名和取消后的仓库状态也要覆盖。
- Gaze 有持久化日志；不要把 GitDock 的会话 Git 输出直接写入这些日志。保留 URL 凭据脱敏和显式导出。
- GitDock LICENSE 是 MIT；复制实质代码时保留其版权和许可文本（2026 nzyyyy）。

## UI 方向

推荐“侧栏集成”：沿用 Gaze 的浅绿灰 / 深绿背景、琥珀色主操作、系统中文 UI 字体和可配置等宽代码字体。左侧现有 Files/Search/Symbols rail 增加 Git 图标和数量角标；侧栏顶部显示当前 Gaze 项目和仓库分支；下方提供更改 / 历史 / 分支 / Stash。

更改列表按“已暂存 / 未暂存 / 冲突”组织。部分暂存的同一路径可同时出现在两组，清楚指示当前差异来自索引还是磁盘。主区上方保持已有文件标签，Git 差异以独立只读标签打开，键包含仓库身份、版本和差异侧，避免与普通文件路径标签冲突。“在编辑器打开”跳回真实工作文件。

特色是让“已暂存 / 未暂存”成为差异页一直可见的上下文，而非藏在右键菜单。首期 unified diff 直接复用 GitDock；并排 diff 后续再决定。新增/删除除颜色外也有 + / − 和状态文案；二进制、大文件、仅模式变化分别显示说明。

备选“独立 Git 工作区”：左侧保留 Gaze 项目树，主区打开 Git 标签，在主区内放更改 / 历史 / 分支导航和文件列表。长时间集中处理 Git 更舒适，但比侧栏方案多一层布局，也占更多宽度。两种方案应二选一作为首期，不同时实现两套导航。

草稿使用示例文件、SHA 和提交数据，不对应真实工作区。用于比较布局与操作反馈，不意味着功能已实现。

## 交互规则

| 场景                                       | 行为                                                                                                                                        |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 进入 Git                                   | 跟随当前项目探测仓库；顶部一直显示项目/仓库，切换项目后清空旧快照并忽略迟到响应                                                             |
| 暂存 / 取消暂存                            | 文件行操作与差异页块操作对应；成功后更新两侧计数；失败不乐观删除文件                                                                        |
| 提交                                       | 暂存为空或消息为空时禁用；显示“提交 N 个已暂存文件”；成功保留未暂存修改、更新历史与待推送数；不自动 push                                    |
| Fetch / Pull / Push                        | 明确独立按钮；显示 upstream 和本地跟踪引用的领先/落后数及上次 Fetch；执行中显示进度/停止，失败展开 Git 输出；不默认自动 Fetch               |
| 分支切换                                   | 弹出可搜索分支选择；当前分支标记；有未保存内容时先处理保存，Git 拒绝覆盖本地改动时保留原分支和文件，提供手动 stash 入口                     |
| 查看历史                                   | 分支筛选只影响历史，不 checkout；选提交 → 文件 → 只读差异；SHA/消息搜索复用 GitDock 语义                                                    |
| 冲突                                       | merge/rebase 状态条持续可见；Base / 当前 / 传入与结果预览；逐块选择完成后才能“写入并暂存”；所有冲突解决后才启用继续；普通提交与流程继续分开 |
| 删除 / 丢弃 / 强推 / 改写历史              | 复用影响预览和确认，列明仓库、分支、文件与后果；强推保留 lease 校验，不退化为 force                                                         |
| 非 Git 目录                                | 显示“该项目尚未初始化 Git”；若首期不接入 init，提示可通过现有终端初始化，再刷新；不要自动 init                                              |
| 缺少 Git / 无远程 / detached HEAD / 空仓库 | 明确显示对应状态；提供配置 Git 路径、管理远程、新建分支或首次提交的下一步；不伪装为零更改                                                   |
| 大文件 / 二进制 / 不支持的冲突             | 提供只读摘要或明确外部工具入口；不加载成普通文本，也不静默写回                                                                              |

键盘：建议 Cmd/Ctrl+Shift+G 进入 Git，复用现有焦点/对话框约定；确认与危险按钮有清晰名称。设计需保持可访问名称、可见焦点、Esc 关闭、焦点恢复；表格和文件列表可键盘操作。具体快捷键落地前检查现有绑定冲突。

## 分期与验收

1. 只读打通：仓库探测、状态、Git 事件、只读 diff、项目切换隔离。验收外部终端 add/commit/checkout 后界面及时更新，同一仓库多项目不串状态。
2. 首个可用闭环：文件与块暂存/取消暂存、提交、Fetch/Pull/Push、本地分支创建/切换，以及编辑器协调。必须具备冲突状态识别和明确恢复入口；暂不移植内部冲突编辑器时，提示在现有终端处理并刷新。验收部分暂存只提交索引，失败/取消保留用户内容。
3. 完整浏览与恢复：历史图、提交详情、文件历史/Blame、分支比较、Stash、三阶段冲突与 continue/abort。验收过期快照、外部改动及不支持冲突均不会覆盖新内容。
4. 高级操作按需求接入：cherry-pick/revert、标签/远程管理、submodule、交互式 rebase、克隆/初始化。

首次闭环的关键路径是“状态与刷新 → 编辑器协调 → 安全写操作 → UI”，不能只完成漂亮的 diff 页面后就认定已具备 Git 管理能力。

保留并适配 GitDock 的已有测试：仓库快照归属、旧 HEAD/旧 hunk 拒绝、部分暂存、冲突外部修改保护、共享 Git dir 写锁、lease、取消进程组。补 Gaze 特有测试：多个标签别名指向同一文件、自动保存与 checkout/discard 互斥、未保存冲突阻止 Git 操作、索引/LSP 刷新、迟到请求不覆盖当前项目、Windows 取消实现。移植完成后再执行双端类型检查、构建、Rust/前端测试和各目标平台验证。
